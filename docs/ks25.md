# Kilosort 2.5 in Python

`kilosort.ks25` implements the Kilosort 2.5 sorting algorithm in Python, PyTorch, and CuPy CUDA kernels. It shares Kilosort 4's preprocessing and drift correction, then uses the 2.5 template-learning, matching-pursuit, merge, split, and cutoff stages. It is a separate pipeline; it does not replace Kilosort 4's `run_kilosort`.

The implementation follows the MATLAB algorithm, but it is not bit-identical to MATLAB. The shared preprocessing uses Kilosort 4's high-pass filtering and local whitening, and processes batches on demand instead of writing MATLAB's `temp_wh.dat`. See [Differences from MATLAB](#differences-from-matlab) for algorithmic and output differences.

For GPU execution, install a CUDA-enabled PyTorch build and a CuPy build compatible with the CUDA runtime. A CPU reference path exists for development, but it is slow and is not the benchmarked path.

## Run a recording

```python
from pathlib import Path
import torch
from kilosort.ks25.run import run_kilosort25

settings = {
    "n_chan_bin": 385,       # Total channels in the binary file, including sync channels
    "fs": 30_000,
    "tmin": 0,
    "tmax": 600,            # Seconds; omit to process the full recording
    "nblocks": 5,            # Drift-correction blocks
    "preset": "tuned",       # Or omit for the MATLAB parameter defaults
}

ops, rez = run_kilosort25(
    settings=settings,
    filename=Path("/path/to/recording.bin"),
    probe_name="NeuroPix1_default.mat",  # Installed probe; must match the recording
    results_dir=Path("/path/to/results"),
    device=torch.device("cuda"),
)
```

`n_chan_bin` is required. Supply either `probe_name` for an installed probe, `settings["probe_path"]` for a probe file, or `probe=` for an already loaded probe dictionary. The function returns the Kilosort-style `ops` dictionary and the KS2.5 `rez` dictionary, and writes the results to `results_dir`. `filename` can also be a list of binary files. See [the function signature](../kilosort/ks25/run.py) for options such as `data_dtype`, `do_CAR`, `invert_sign`, and `bad_channels`.

### Settings

Pass KS2.5 and shared Kilosort 4 settings as top-level keys in `settings`. Shared settings include `fs`, `batch_size`, `nt`, `nt0min`, `nblocks`, `tmin`, `tmax`, `highpass_cutoff`, `whitening_range`, and `nskip`; see [Kilosort parameters](parameters.rst) for their definitions. `nblocks=5` in the example is explicit; the shared Kilosort 4 default is `1`.

`preset="matlab"` is the default. `preset="tuned"` uses `Th=(8, 4)` and `momentum=(20, 100)`, chosen from the sim600 experiment below. Explicit values in `settings` override the preset. The tuned preset is a starting point measured on that dataset, not a guarantee for other recordings.

| KS2.5 key | Default | Meaning |
| --- | --- | --- |
| `preset` | `"matlab"` | Select `"matlab"` or `"tuned"` parameter values. |
| `Th` | `(10, 4)` | Matching-pursuit thresholds for learning and final extraction. |
| `lam` | `10` | Template-amplitude penalty. |
| `AUCsplit` | `0.9` | Split isolation threshold. |
| `minFR` | `1/50` | Minimum template firing rate in Hz during triage. |
| `momentum` | `(20, 400)` | Start and end of the learning momentum schedule. |
| `sigmaMask` | `30` | Spatial neighborhood mask scale. |
| `spkTh` | `-6` | Single-channel negative threshold for isolated snippets used to learn the initial waveforms. |
| `nfilt_factor` | `4` | Maximum number of learned templates per recording channel. |
| `useStableMode` | `1` | Use stable matching-pursuit subtraction and averaging in both passes; `0` uses the faster non-stable path. |
| `NchanNear`, `Nnearest` | `32`, `32` | Number of neighboring channels and neighboring templates, respectively, limited by channel count. |
| `NrankPC` | `6` | Number of initial waveform prototypes and PCs; the learned template rank is fixed at 3. |
| `nInnerIter` | `60` | Maximum matching-pursuit iterations per batch. |
| `loc_range`, `long_range` | `(5, 4)`, `(30, 6)` | Time/channel radii for local minima and isolated-peak selection. |
| `learn_batches_max` | `None` | Optional cap on the number of drift-ordered training batches; a regular subset is used. This can change sorting results. |
| `fix_split_swap`, `fix_merge_pc` | `True`, `True` | Enable the split waveform assignment and merged-PC channel fixes described below. |
| `matlab_tail` | `False` | When `True`, use MATLAB's truncated CUDA scan ranges for candidate detection and matching pursuit. |

Template rank is fixed at 3, and the number of channels summed in candidate detection is `min(Nchan, NchanNear, 7)`. `ThPre` is not used by this KS2.5 path.

### Optimization and diagnostic switches

`KS_FASTEST_OFF` is a comma-separated list of optimization names to disable. The KS2.5-specific names are:

| Name | Disabled behavior |
| --- | --- |
| `ks25_dwu_fused` | Use the PyTorch expression instead of the fused CUDA running-template update. |
| `ks25_split_batch` | Use the scalar split path instead of batched split processing. |
| `ks25_split_em_fused` | Use batched PyTorch EM instead of the fused CUDA EM iterations. |
| `ks25_split_cov_fused` | Use the matrix multiplication covariance path instead of the fused covariance kernel. |
| `ks25_split_ccg_threads` | Run split CCG work serially. |
| `ks25_cutoff_threads` | Run cutoff work serially. |

For example, in PowerShell:

```powershell
$env:KS_FASTEST_OFF = 'ks25_dwu_fused,ks25_split_batch'
```

Shared Kilosort switches such as `hpfilter`, `prefetch_depth`, `h2d_overlap`, and `mmap_save` also affect the shared I/O or preprocessing path. Optimizations can differ in floating-point operation order; use the switches and validate outputs on the target data when reproducibility matters.

Set `KS25_PROFILE=1` to log per-stage learning and tracking timings. These measurements synchronize the CUDA device around each measured stage and therefore add overhead; they are diagnostic timings, not production throughput. Set `KS25_DUMP_REZ` to a file path to save the `rez` dictionary with `torch.save` immediately after tracking and before merge/split/cutoff. For example:

```powershell
$env:KS25_PROFILE = '1'
$env:KS25_DUMP_REZ = 'D:/results/ks25-before-postprocess.pt'
```

The dump can be large and can contain GPU tensors. Load it with `torch.load`, using `map_location` if necessary.

## Differences from MATLAB

- **Preprocessing and drift:** Kilosort 4's preprocessing and drift correction are used. Batches are filtered and whitened on demand in unit-variance scale, rather than being stored in a scaled int16 `temp_wh.dat`. These choices can change results.
- **Batch tails and boundaries:** the original CUDA loop bounds leave a portion of each batch tail unscanned. By default, this port scans the full valid range. Set `settings["matlab_tail"] = True` to reproduce the MATLAB CUDA tail bounds for `get_spikes2` and `mpnu8` on the CUDA path; the slow torch reference path does not implement this switch. Final extraction keeps spike starts in the central batch window only and converts them to absolute peak sample times; the per-template waveform and count aggregates still include padded samples, as in MATLAB.
- **Candidate best-filter initialization:** candidate detection resets the maximum for each time point. The MATLAB CUDA implementation retains a maximum across grid-stride iterations, which can copy head values into the unfiltered tail. This correction has no separate compatibility switch.
- **Candidate and output ordering:** candidate spikes are ordered by time rather than MATLAB's nondeterministic atomic increment order. Phy output is stably sorted by spike time, with features reordered along with spikes. Matching-pursuit stable mode also orders spikes for waveform averaging.
- **Split waveform assignment:** the default `fix_split_swap=True` assigns split waveforms to the corresponding spike groups. Set `fix_split_swap=False` for MATLAB's swapped c1/c2 assignment.
- **Merged PC features:** the default `fix_merge_pc=True` remaps a merged unit's PC feature channels into the target unit's neighborhood. A target channel absent from the source neighborhood is filled with zero; features are not reprojected from the recording. Set `fix_merge_pc=False` to retain MATLAB's unremapped features.
- **Stable mode:** `useStableMode=1` is the default for learning and tracking. MATLAB's `trackAndSort` forces non-stable mode; set `useStableMode=0` to use non-stable matching pursuit in both Python passes. This is a single setting for both passes.
- **Template decomposition and accumulation:** CUDA uses neighborhood-only calculations where the omitted entries are zero, and reorganizes several update operations. Floating-point summation and near-tie selection can differ from MATLAB; bitwise identity is not promised. The tracking decomposition is computed once for its fixed templates rather than warm-started repeatedly on every batch, which can also produce small numerical differences.
- **Degenerate cases and exported features:** zero-count final template averages use a denominator of at least one. Singular whitening matrices use a pseudoinverse for export. As in the source algorithm, template features are not recomputed after merge/split neighborhood changes, so `template_features.npy` and the final neighbor table can differ in their interpretation.

Low-level `kernels.mpnu8` also exposes `early_stop` and `sync_every`; its default stops after a no-new-spikes iteration and checks progress periodically. These are kernel-call options, not entries in `KS_FASTEST_OFF`.

## Output files

The results directory contains Phy-compatible files:

- Spike assignments and amplitudes: `spike_times.npy`, `spike_templates.npy`, `spike_clusters.npy`, `amplitudes.npy`.
- Waveforms and geometry: `templates.npy`, `templates_ind.npy`, `channel_map.npy`, `channel_positions.npy`, `similar_templates.npy`.
- Features: `template_features.npy`, `template_feature_ind.npy`, `pc_features.npy`, `pc_feature_ind.npy`.
- Whitening: `whitening_mat.npy`, `whitening_mat_inv.npy`.
- Cluster metadata: `cluster_KSLabel.tsv`, `cluster_ContamPct.tsv`, `cluster_Amplitude.tsv`, `cluster_group.tsv`.
- Phy configuration: `params.py`.

`ops.npy` is also saved for Kilosort-compatible consumers. It includes preprocessing and drift information and KS2.5 result fields. `ops["wPCA"]` retains the initial PCs (six by default), while `ops["wPCA25"]` contains the PCs used for KS2.5 features. `params.py` references the original raw binary, with the channel map and whitening matrices needed for that representation. In Phy, open the results directory with `phy template-gui params.py`.

## Benchmark results

These measurements are from the first 600 seconds of the `sim_med_drift` simulation (600 ground-truth units, 385-channel int16 data at 30 kHz), on Windows 11 with an RTX 4070 SUPER, Ryzen 5 9600X, and 61.6 GB RAM. They are historical measurements of specific snapshots, not a promise for other data or hardware. Ground-truth scores are the number of correctly recovered units out of 600. MATLAB used `NT=65472` and 275 batches; Python used 60,000-sample batches and 300 batches.

### MATLAB Kilosort 2.5 baseline

| Stage | Seconds |
| --- | ---: |
| `preprocessDataSub` | 57.7 |
| `datashift2` | 86.3 |
| `learnAndSolve8b` (approximately 64 s learning + 44 s tracking) | 108.2 |
| `find_merges` | 3.1 |
| `splitAllClusters` | 43.0 |
| `set_cutoff` | 5.4 |
| `rezToPhy` | 1.2 |
| **Total** | **305.5** |

MATLAB recovered **399/600** units; it produced 753 templates and 533 good units. The comparison Kilosort 4 fastest run recovered 512/600; upstream Kilosort 4 main recovered 516/600.

### Python v2

The v2a and v2b runs used the same code snapshot and MATLAB-default parameter values. Their outputs were bit-identical. A dash denotes a stage not separately reported for v2b.

| Stage | v2a (s) | v2b (s) |
| --- | ---: | ---: |
| Preprocessing | 1.2 | — |
| Drift | 11.7 | 8.5 |
| Initial waveforms / PCs | 0.4 | — |
| Learning | 21.3 | 21.0 |
| Tracking | 15.8 | 15.9 |
| Merge | 0.6 | — |
| Split | 8.6 | 8.7 |
| Cutoff | 1.0 | — |
| Output | 3.0 | — |
| **Total** | **63.6** | **59.8** |

v2a recovered **441/600** units, with 1,844,077 spikes, 772 clusters, and 547 good units. The v2a total was about 4.8× faster than the MATLAB baseline. v3 results will be added when available.
